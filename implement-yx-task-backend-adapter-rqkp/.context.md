# Goal
Implement the first TaskBackend adapter without leaking yx behavior into Temporal workflows.

# Scope
- Implement candidate listing, claim, release, completion, context, and pull-request field operations.
- Synchronize repository state through adapter-owned yx commands.
- Map review candidates and root-level dispatch metadata into backend-neutral candidates.

# Implementation
The root yak owns @g2g and @priority:<integer>; descendants inherit those tags. Exclude malformed or missing root metadata, dispatch todo descendants deepest-first within root priority, and expose the root only as a final review after all descendants are terminal. Keep task-tool parsing and mutations in this adapter. Follow docs/plans/2026-09-05-task-dispatch-design.md.

# Acceptance Criteria
- [ ] Candidate ordering is deterministic by root priority, tree depth, review kind, creation time, and stable ID.
- [ ] Root metadata is inherited without copying tags onto descendants.
- [ ] Root yaks are review-only and wait for terminal descendants.
- [ ] Claim, release, completion, context, PR fields, and synchronization use adapter-owned yx behavior.
- [ ] Invalid candidates are skipped and logged without mutation.
- [ ] Safe reads have bounded retries; mutating operations have one attempt unless idempotent.

# Tests
- Unit-test tree flattening, inherited metadata, final-review gating, ordering, exclusions, malformed metadata, lifecycle commands, and logging.
- Run `npm test` and `npm run build`.

# Dependencies
- Backend-neutral TaskBackend and DispatchCandidate contracts.

# Non-Goals
- Jira or Linear support.
- Automatic priority assignment or aging.
- Temporal orchestration and workflow-specific parsing.
