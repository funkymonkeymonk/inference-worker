# Goal
Evaluate stacked pull requests as a future dispatch model so dependent implementation yaks can be developed and reviewed in parallel.

# Scope
Define how yaks expose parent branch or PR dependencies, how isolated jj workspaces are based on those revisions, how child PRs are rebased when parents change, and how merge ordering interacts with WorkItemWorkflow and the yx adapter.

# Implementation
This is a feature idea only. Before implementation, update the task-dispatch design with an explicit stacked-PR lifecycle and decide whether backend metadata or repository conventions provide the stack relationship. Preserve deterministic workflows, backend-owned task behavior, and Activity-owned side effects.

# Acceptance Criteria
- A future design explains branch/base revision metadata and stack ordering.
- The design covers parent updates, review feedback, merge sequencing, closed or failed parent PRs, cancellation, and workspace cleanup.
- The design defines when dependent yaks may receive @g2g and how the adapter prevents unsafe dispatch.
- No current dispatcher, workflow, adapter, or Nix behavior changes as part of this idea.

# Tests
Future design must identify adapter, workspace, workflow, and integration tests before implementation begins.

# Dependencies
The current task-dispatch design and WorkItemWorkflow behavior.

# Non-Goals
Do not implement stacked branches, stacked PR creation, rebasing, dependency metadata, or parallel dispatch in the current task-dispatch work.
