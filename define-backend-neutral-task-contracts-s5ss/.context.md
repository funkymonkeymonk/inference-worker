# Goal
Define serializable interfaces that let Temporal orchestration use one configured task backend without knowing yx, Jira, or Linear concepts.

# Scope
- Define TaskBackend, DispatchCandidate, WorkItem input/state, backend configuration, and Activity contracts.
- Keep candidate data limited to stable ID, title, context, and serialized workflow input.

# Implementation
Keep workflow boundaries deterministic and serializable. Do not import yaketyyak worker code or invoke task tools from workflow modules. Preserve the root-owned dispatch metadata model as an adapter concern rather than embedding it in Temporal types.

# Acceptance Criteria
- [ ] The contract expresses candidate listing, claim, release, completion, context, and pull-request attachment.
- [ ] Workflow and Activity inputs contain no yx-specific tags or command details.
- [ ] Types support review state, pull-request state, workspace, feedback round, and AgentPolicy.
- [ ] Existing direct inference types remain compatible.

# Tests
- Add compile-time and serialization-focused tests for valid inputs, candidate data, workflow state, and backend-neutral boundaries.
- Run `npm test` and `npm run build`.

# Dependencies
- None.

# Non-Goals
- Implementing a backend.
- Process execution, filesystem access, or network calls.
- Priority calculation or tree traversal.
