# Goal
Make the canonical test commands actually run every test file in the repository, regardless of which POSIX shell npm invokes.

# Scope
- `package.json` `test` and `test:integration` scripts (the `*.test.ts` glob patterns).

# Problem (found while implementing worker startup validation)
`npm test` runs via `sh`, where `**` is a single path segment, not recursive. So:
- `src/**/*.test.ts` matches only one level deep (12 files: `src/activities/*`, `src/backends/*`, `src/ui/*`, `src/workflows/*`) and **silently skips the 7 top-level `src/*.test.ts` files** (`config`, `dispatch`, `task-contracts`, `temporal-address`, `worker-shutdown`, `workflow-id`, `worker-runtime`).
- Result: `npm test` runs 69 tests; the real set is 95 (16 files in `src`, 3 in `integration`).
- `integration/**/*.test.ts` has the same defect (0 files are one level deep, so the 3 top-level `integration/*.test.ts` files are skipped).

# Acceptance Criteria
- [ ] `npm test` runs every `src` test file: both `src/*.test.ts` (7) and `src/*/*.test.ts` (9) — 16 files total.
- [ ] `npm test:integration` runs all 3 `integration/*.test.ts` files.
- [ ] The pattern is correct in both `sh` and `zsh` (do not rely on `globstar` or recursive `**`).
- [ ] `npm test` and `npm run test:integration` pass with the corrected glob.

# Tests
- Run `npm test`; confirm the test count rises from 69 to 95 and no file is skipped.
- Run `npm run test:integration`; confirm all 3 integration suites execute.

# Dependencies
- None. (The pre-existing top-level and nested tests already pass when run directly via `npx tsx --test`.)

# Non-Goals
- Do not move or restructure test files.
- Do not add new tests; only correct the selection glob.
