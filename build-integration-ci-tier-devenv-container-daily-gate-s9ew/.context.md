# Goal
Run the Temporal-backed integration and worker-integration suites in CI via the repo's devenv environment (NOT an OCI container), on PR (advisory) and daily-when-main-changed.

## Approach decision
- Chosen: **devenv (no container)** — in CI: install nix + devenv, `devenv up -d temporal` to start the repo's existing services.temporal (namespaces inference + integration-inference already configured), then run the suite in the devenv shell.
- Chosen over: the original "devenv container" (OCI image) plan, because (a) local docker/colima is down so the container path could not be pre-validated, and (b) the no-container path was fully validated end-to-end (5/5 + 2/2 in a fresh clone against live Temporal).
- Runtime (validated): temporal-cli 1.8.2 / yx / jj 0.44.0 / node 24 from the repo devenv env; `temporal server start-dev -n inference -n integration-inference` (or `devenv up -d temporal`) provides the live Temporal at 127.0.0.1:7233.

## Findings (bug fixed)
- test:integration used "tsx --test --test-concurrency=1 integration/**/*.test.ts" which matches ZERO files in sh/dash (the 3 test files sit at integration/ top level, and **/ requires a subdir) — the same one-level-deep glob bug fixed for the unit script by PR #2. Fixed to "integration/*.test.ts integration/*/*.test.ts".
- A fresh CI clone has no .jj/ (gitignored); the worker-shaves-yak tests need jj, so CI must run `jj git init` first (validated: suite passes 5/5 after it).

# Acceptance Criteria
- [ ] CI runs the 5 integration tests (2 of which are the worker-integration) against live Temporal in the devenv env.

- [ ] Daily run executes only when main advanced since the last successful run; the inference-worker-ci-state marker is updated.
- [ ] jj git init + npm ci + build + integration suite all succeed in a fresh clone (validated locally).
