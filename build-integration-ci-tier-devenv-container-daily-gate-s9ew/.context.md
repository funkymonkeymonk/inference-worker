# Goal
Run the Temporal-backed integration and worker-integration suites in CI via the repo's devenv environment (NOT an OCI container), on PR (advisory) and daily-when-main-changed.

## Result: DONE
PR #4 (https://github.com/funkymonkeymonk/inference-worker/pull/4) adds `.github/workflows/integration.yml` and a `yaksYx` derivation to `devenv.nix`.

## What was built
- integration-on-pr: advisory, runs on every pull request (never blocks; the unit tier is the required gate).
- integration-on-main: nightly (03:17 UTC), runs only when main advanced since the last successful integration run; on success records the commit in inference-worker-ci-state/state.json (lastSuccessfulMainSha).
- Flow: install-nix-action + cachix(devenv) + `nix profile add nixpkgs#devenv` -> `devenv up -d temporal` (builds env, starts services.temporal: namespaces inference + integration-inference) -> wait SERVING -> `devenv shell jj git init` -> `devenv shell npm ci` + build -> `devenv shell npx tsx --test --test-concurrency=1 integration/*.test.ts`.

## Root cause fixed
The devenv env's pkgs.yx was nixpkgs' yx (a YAML parser), NOT the yaks task tool. So the worker and the worker-shaves-yak tests shelled out to a yx that rejected their add/list/tag/state commands (3 non-worker tests passed, 2 worker tests crashed at ~50ms). Added a yaksYx derivation (static-pie prebuilt binary, aarch64-darwin + x86_64-linux, pinned mattwynne/yaks v0.2.0) and swapped it into the env.

## Verified (2 independent confirmations)
1. Fresh-clone local validation: devenv up -d temporal (SERVING, both namespaces), jj git init, npm ci + build, all 5 integration tests (2 of which are the worker-integration) pass (5/5).
2. GitHub Actions CI (x86_64-linux) on PR #4: integration-on-pr PASS, 5/5 (the "agent timed out" warnings are the expected max-depth-failure test, which passed). integration-on-main correctly skipping (schedule-only).

## Approach decision (chose devenv-no-container over the original "devenv container" plan)
The container (OCI image) path could not be pre-validated (local docker/colima down), and the no-container path was fully validated end-to-end in a fresh clone and on CI.
